# ADR028: Additive consolidation of saved exact-ID shadow follows

Date:17 October2026. Status: approved operator direction; copied batch tested,
independent review and private activation pending. No new schema/service.

## Decision and scope

Consolidate existing local evidence in bounded batches before new acquisition or
ranking expansion. Reuse ADR025's three-table SQLite graph and Review follow
search. First batch reads numeric-endpoint rows from cache.db.shadow_edge and
qualifies endpoint profiles using existing independent observations or explicitly
public saved provider objects. Do not use published Archive profiles as an
unavailable-source fallback. Never merge shadow:handle identifiers by name.

Keep source_id→target_id for both outbound and inbound records: the capture
producer already stores follower→followed for inbound lists. Raw selected rows
are preserved inside private content-addressed snapshots with original SQLite
table, primary-key fields and date strings. They are stored-row evidence, not
invented HTTP receipts. Naive capture times remain timezone-unspecified.

Caller owns a copied graph and transaction. Repeat import is idempotent; prior
graph rows, raw databases, tags/events and outreach stores remain unchanged.
Report skipped endpoints and deferred aliases explicitly, not as missing follows.
Review shows the original capture channel/direction/time basis and source fields.
Follows establish neither friendship, domain competence nor group membership.

## Activation and rollback

After code review and consumer checks, graph-only adoption uses the existing
managed refresh lock. A new release references the unchanged previous Archive
package/index and the derived graph; the previous release remains readable.
Publication checks remain unchanged: no October16 activation or visibility
override is implied by local evidence consolidation. Retained Archive material
can still be hidden. No fetching, spend, automatic entity merge or outreach.

## Finite acceptance and next batch

Verify exact IDs beyond JS integer range, inbound direction, protected/flagged
profile refusal, malformed metadata rollback, alias deferral, prior-row retention,
repeat import, existing capture-receipt compatibility and unknown timezone UI.
Prove a real newly reachable account through Review's existing source filter,
follow evidence and exact dossier, with tag bytes/counts unchanged.

Next batches: unresolved handle-only observations need a distinct identity-safe
consumer; saved typed engagement needs its own source eligibility and target
resolution. Neither gap justifies a new graph service or inferred psychology.
The local batch command is scripts/verify_shadow_follow_batch.py; it prints
qualifying/excluded counts and never adopts a graph by default.
