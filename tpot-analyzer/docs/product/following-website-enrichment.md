# Following-account website enrichment

## No-page audit and recovery checkpoint, 22 October 2026

The 629 zero-page outcomes were pipeline outcomes, not evidence of absent websites.
Exclusive check groups: 610 had a recorded robots-disallowed result, nine had
unavailable robots metadata without that result, ten had only intentionally
skipped platform links. Old instrumentation conflated robots rules with robots.txt
HTTP 401/403/429 and retained no basis, so do not retrospectively assert a true
robots prohibition in every case. 619 accounts had shortener roots. Eleven also
had page-fetch errors; twelve retained 22 unvisited roots, all shorteners.

Saved-link audit finds 56 unused literal URLs across 47 accounts. Conservatively
withholding publication-dependent witnesses leaves 30 independently witnessed
URLs across 27 accounts. Raw-cache audit separately finds 29 readable HTML pages
unbound to visible current profile roots; the importer therefore projected none.
A private conservative candidate subset recovers 27 original page observations
across 25 accounts. They remain dated historical research, not newly served pages
or permission to manufacture current profile links. Original bytes remain intact.

Bounded public checks cover those 30 destinations: 15 readable non-generic bodies,
one generic service page, three title/shell-only outcomes, eleven unavailable.
Search-tool snapshots may be cached; check date is not necessarily source date.
A separate twelve-handle pilot finds useful GitHub, personal-site, newsletter and
social-link bridges, including different cross-platform aliases, and preserves
name collisions, stale Mastodon candidates and inaccessible destinations.
This is not all-account cross-platform coverage or a measured match precision.

Username, work and public network/community context generate and rank candidates;
literal self-links, reciprocal handles and distinctive-source corroboration are
separate supporting evidence. Similarity alone establishes neither identity nor
sensitive traits. No inference of religious affiliation or other sensitive
attributes follows from these public link observations.

All detailed ledgers, historical bodies and public-check notes remain private;
the private handoff includes a read-only verification script. Raw/Takes/tag
preservation remains 93 assignments/93 events; active graph, runtime and rollback
are unchanged. No paid fetching, outreach or push. Next slice: expose qualified
historical/research candidates separately from profile-bound pages, then continue
bounded self-link discovery. Do not solve the display gap by weakening source
admission or Archive publication policy.

### What failed and remains partial

- The initial packet checker overwrote duplicate-URL page observations and
  falsely rejected a retained discovery link. Synthetic RED/GREEN and independent
  source-only review support accumulating observations; graph admission remains
  a separate exact-source/path check, not URL-only ownership inference.
- One private acceptance script initially used `handle` rather than the locator
  DTO's `username`; it stopped before data writes. Corrected after inspecting the
  actual reader contract. No production API workaround was introduced.
- An initial copied import stopped on non-UTF-8 bodies. Preflight now uses the
  existing strict decoder; six pages are deferred with original packet bytes
  retained. Do not call them empty pages or silently rewrite raw bytes.
- Direct link/host bounds leave additional cache rows unadmitted. Robots refusal,
  unavailable reads, unsupported media and no saved root remain distinct unknowns.
  Saved literal destination mappings helped inspect previously unvisited direct
  roots without retrying refused shorteners or inferring cross-account identity.
- Current Archive publication advanced independently during the pass; older
  package profiles remain policy-hidden while independent evidence works. This
  task neither refreshes that package nor treats disappearance as data loss.

Follow-up work: explicit encoding-aware projections retaining original bytes;
source-qualified www/subdomain/contact-page variants; and permitted website
discovery for no-link accounts. Broad follower expansion, identity confirmation,
contact delivery, tag calibration and cluster-recovery evaluation remain separate.

## Outcome and operating slice, 22 October 2026

For every account in a frozen following capture, reuse exact-account saved
research, then inspect public bio websites in disjoint batches. In private
Review, the existing contact card and cached-page/source panels show newly
connected email strings, message-form declarations and social-profile links.
Codex/root is integration owner in the authoritative clean-main checkout;
Luna workers own disjoint acquisition packets, never the shared graph or tags.

This is contact/evidence coverage, not cluster membership, identity resolution,
email ownership, deliverability or outreach. Organisation inboxes are retained
with their page context. There is no personal-name-only email filter. Forms are
not submitted. A social link does not prove who controls the destination.

## Finite pass and assumptions

- Freeze the exact-ID denominator before processing; maintain privacy holds,
  no-saved-website, unchecked, reused, fetched and unavailable separately.
- H1, confidence 0.9: reuse can connect useful evidence without new fetches.
  Falsifier: no new source-qualified page/clue observations on the copied graph.
- H2, confidence 0.8: bio websites and directly linked contact/about pages add
  usable contact affordances beyond the X profile. Record observed additions,
  failed reads and leftover candidates, not just successful examples.
- Each account initially gets at most three admitted profile-root URLs and two
  explicitly linked same-site contact/about candidates. Saved pages are reused
  before network requests, with original dates. An attempted bounded pass is not
  exhaustive research; unvisited candidates remain explicit.
- Use the existing public-URL guard, bounded responses and timeouts. Respect
  robots refusals; do not authenticate, bypass challenges, submit forms, infer
  private contacts, or treat website text as agent instructions.

## Integration and acceptance

Raw HTML/cache evidence and account packets remain private and resumable.
Recompute extraction from retained bytes before importing. Root alone imports
into a fresh copied relationship sidecar using the existing three-table schema,
prior-row retention, repeat-import and integrity checks. Keep the old graph and
unchanged post index for rollback. Never write to the original archive/cache,
Takes or curator tag stores for this task.

`project_cached_websites(..., allow_discovered=True)` opt-in accepts only a direct
same-host contact/about child whose retained parent page contains that exact
link. The child keeps both the captured profile association and the parent
page-link reference. Read-side visibility requires the same source path and
parent policy. Existing callers remain root-only by default. There is no new
crawler service, identity schema, reviewed-contact promotion or recursive crawl.

Acceptance: source-shaped synthetic child email/form/social evidence reaches
existing preview/card/search; an orphan, other account or hidden parent cannot
qualify it. Then focused/combined checks and independent code-only review; real
exact-account dossier/card/source inspection after each adopted batch. Compare
tag/source preservation receipts before and after; never create a real tag merely
to test the feature. No paid acquisition, outreach or push.

Run `scripts/verify_following_website_packets.py --cohort <private-cohort.json>
--packets <private-worker-dirs...>` for a human-readable read-only packet check.
Use the existing cached-website graph verifier for root-only batches; the
discovered-page importer remains an explicit option in the copied integration.
